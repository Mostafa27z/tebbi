نظرة عامة • Overview

منصة الربط البرمجي للشركاء (Tebiby Connect API)

واجهة برمجية معيارية موجهة لربط المستشفيات والعيادات الكبرى (HIS) وتطبيقات الطرف الثالث مع منصة طبيبي للرعاية الصحية بالمملكة العربية السعودية، متوافقة كلياً مع نظام حماية البيانات الشخصية السعودي (PDPL) واللوائح الصحية المعتمدة.

الروابط الأساسية للبيئات (Base URLs):
Live (Production): https://api.tebiby.com/v1/connect
Sandbox (Testing): https://sandbox-api.tebiby.com/v1/connect
الأمان والمصادقة • Dual-Key Auth

نظام المصادقة المزدوج (Dual-Key Authentication)

تعتمد المنصة نوعين من المفاتيح لحماية السجلات الطبية وعزل البيانات وفقاً لبيئة الاستدعاء:

أنواع المفاتيح وترويساتها المعتمدة
نوع المفتاح البادئة (Prefix) طريقة الإرسال (Header) نطاق الاستخدام المسموح
المفتاح العام (Publishable Key) tb_live_pk_... / tb_test_pk_... X-Publishable-Key: <key> مخصص للمتصفحات وتطبيقات الهواتف. قراءة الدليل العام وتتبع الطابور فقط.
المفتاح السري (Secret Key) tb_live_sk_... / tb_test_sk_... Authorization: Bearer <sk> يُحظر كشفه في المتصفحات. يُستخدم بين الخوادم حصراً (Server-to-Server) للحجز والإلغاء والـ Webhooks.
توكن نية الحجز (Intent Token) bit_live_... / bit_test_... Authorization: Bearer <bit> توكن موقع صالح لـ 15 دقيقة فقط، مخصص لتأكيد وإنشاء الحجز النهائي عبر مسار الحجز.
الموثوقية والشبكة • Reliability

ترويسة منع التكرار المعاملاتية (Idempotency-Key)

كافة المسارات التعديلية للمواعيد (POST /appointments و POST /appointments/{ref}/cancel) تتطلب إلزامياً ترويسة منع التكرار لمنع الحجوزات المزدوجة أو خصم المبالغ مرتين في حال انقطاع اتصال شبكة العميل.

الترويسة الإلزامية: Idempotency-Key: <UUID-v4>
غياب هذه الترويسة في أي طلب حجز أو إلغاء يؤدي فوراً إلى رفض الطلب بكود 400 Bad Request والرمز ERR_IDEMPOTENCY_KEY_REQUIRED. عند إعادة إرسال نفس الطلب بنفس المفتاح، تُعاد الاستجابة الأصلية فورياً مع الترويسة Idempotent-Replay: true.

استعراض الفروع المصرح بها (List Branches)

يُرجع قائمة الفروع والمراكز الطبية المسموح لمفتاحك بالوصول إليها وفق مبدأ الحرمان الافتراضي (Default-Deny).

GET /branches
Scope: read PK / SK

الترويسةالنوعالوصف
X-Publishable-Key string أو المفتاح العام للواجهات المفتوحة.
Authorization string أو Bearer tb_live_sk_... للخوادم.

فحص المواعيد • Availability Engine

فحص المواعيد المتاحة للعيادة (Check Availability)

يستعلم محرك الحجز في الزمن الحقيقي لحساب الخانات الزمنية الدقيقة للطبيب بالمنشأة، مع إرجاع حدود الطاقة الاستيعابية الفورية وقائمة الانتظار وحجب الأوقات المنقضية بتوقيت الرياض.

GET /doctors/{doctor_id}/availability
Scope: read PK / SK
المعاملات المطلوبة (Query Parameters)
المعاملالنوعالوصف والقيود

service_id integer (query) اختياري لحساب مدة الخانة وفق مدة الخدمة بدقة.

الحالة البرمجيةالدلالة التشغيلية

جلسة الحجز المسبقة • Pre-Booking Intent

توليد نية الحجز الموقعة (Create Booking Intent)

POST /booking-intents
Scope: book Secret Key Only
حمولة الطلب (Request Payload JSON)

محرك الحجز الفعلي • Atomic Booking

POST /facilities/{facility_id}/appointments
Scope: book Idempotency-Key

الترويسةالقيمة المطلوبةالأثر البرمجي

إلغاء المواعيد • State Machine

إلغاء الموعد المحجوز (Cancel Appointment)

إلغاء محمي بآلة الحالات الصارمة؛ يُسمح بالإلغاء فقط في الحالات الابتدائية، ويُحظر فوراً إذا دخل المريض غرفة الفحص السريري مع الطبيب. الإلغاء متكرر بأمان (Idempotent 200 OK).

POST /facilities/{facility_id}/appointments/{booking_reference}/cancel
Scope: cancel Secret Key
قواعد آلة حالات الإلغاء (State Transitions)
حالة الموعد الحاليةإمكانية الإلغاءالاستجابة الناتجة
pending_confirmation / confirmed / checked_in مسموح يتم الإلغاء فوراً وتسجيل سبب الإلغاء وإرجاع 200 OK.
cancelled (ملغي مسبقاً) Idempotent يُعاد نجاح فوري 200 OK بالحالة الحالية دون تكرار الـ Webhooks.
in_progress / completed محظور قطيعاً يُرفض الطلب فوراً بكود 409 Conflict والرمز ERR_INVALID_STATE. 
curl -X POST "https://sandbox-api.tebiby.com/v1/connect/facilities/10/appointments/TB-SR8492/cancel" \
  -H "Authorization: Bearer tb_test_sk_sec9988776655" \
  -H "Idempotency-Key: a1b2c3d4-e5f6-789a-bcde-f0123456789a" \
  -H "Content-Type: application/json" \
  -d '{
    "cancellation_reason": "طلب المريض - ظروف خاصة"
  }'
نموذج الاستجابة 
{
  "booking_reference": "TB-SR8492",
  "external_appointment_id": "HOSP-4491",
  "status": "cancelled",
  "cancelled_at": "2026-11-22T18:25:00Z",
  "cancellation_reason": "طلب المريض - ظروف خاصة"

معايير الأخطاء • RFC 7807

كتالوج رموز الأخطاء المعياري (Error Codes Catalog)

تُعاد كافة ردود الأخطاء بترويسة Content-Type: application/problem+json; charset=utf-8 بصيغة Problem Details المعتمدة دولياً.

جدول رموز الأخطاء، المعنى البرمجي، والإجراء المطلوب للمطور
رمز الخطأ (Code) كود HTTP الوصف البرمجي الإجراء الموصى به
ERR_UNAUTHORIZED 401 مفتاح API مفقود أو غير صالح أو منتهي الصلاحية. التحقق من ترويسة Authorization أو X-Publishable-Key وصلاحية البيئة.
ERR_FORBIDDEN_SCOPE 403 المنشأة مصرح بها ولكن المفتاح يفتقر لصلاحية العملية المحددة. إضافة الصلاحية (book, cancel) للمفتاح في لوحة التحكم.
ERR_RESOURCE_NOT_FOUND 404 المورد غير موجود أو يتبع لمنشأة خارج نطاق مفتاحك (Fail-Silent). التأكد من صحة المعرف وشموله ضمن صلاحيات مفتاحك.
ERR_IDEMPOTENCY_KEY_REQUIRED 400 ترويسة منع التكرار Idempotency-Key مفقودة في طلب تعديلي. توليد وتمرير UUID v4 في ترويسة Idempotency-Key.
ERR_VALIDATION_FAILED 422 فشل التحقق من المدخلات (مثل غياب external_patient_id). مراجعة مصفوفة invalid_params وتصحيح الحقول.
ERR_PRICE_MISMATCH 422 السعر المتوقع لا يطابق السعر المعتمد للخدمة شامل الضريبة 15%. جلب أحدث قائمة أسعار عبر GET /services وإعادة المحاولة.
ERR_SLOT_NOT_AVAILABLE 422 اكتملت الطاقة الاستيعابية الفورية وقائمة الانتظار في هذا الموعد. اختيار موعد بديل عبر استعلام التوفر GET /availability.
ERR_DAILY_PHONE_LIMIT 422 تجاوز رقم الجوال الحد الأقصى للحجوزات اليومية (5 حجوزات/يوم). إبلاغ المريض بضرورة مراجعة إدارة المركز الطبي.
ERR_PATIENT_IDENTITY_CONFLICT 409 المعرف الخارجي للمريض مسجل مسبقاً بهاتف مختلف؛ تعديل الهوية محظور. التأكد من دقة ربط معرف المريض وعدم استخدامه لمرضى مختلفين.
ERR_CONFLICT_IN_FLIGHT 409 يوجد طلب متطابق بنفس الـ Idempotency-Key قيد المعالجة بالخادم حالياً. الانتظار من ثانيتين إلى 3 ثوانٍ قبل إعادة المحاولة.
ERR_INTENT_EXPIRED_OR_USED 410 توكن نية الحجز استُهلك مسبقاً أو تجاوز مهلته (15 دقيقة من إنشائه). توليد جلسة نية حجز جديدة عبر POST /booking-intents.
ERR_RATE_LIMIT_EXCEEDED 429 تجاوز حد الطلبات المسموح به في الدقيقة (Rate Limit). تطبيق خوارزمية التراجع الأسي (Exponential Backoff).
ERR_NOT_IMPLEMENTED 501 المسار محجوز للمرحلة القادمة (مثل إعادة الجدولة). مراجعة وثائق الإصدار الحالي.
